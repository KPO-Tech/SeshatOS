# Translating the interface

The desktop interface speaks English and French. **A person's text is translated; a machine's text never is.**

## Where things live

- Catalogues: `seshat-desktop/src/renderer/i18n/locales/<language>/<namespace>.json`, one file per language and per namespace, read when needed. English (`en`) is the source and the fallback: a text a language lacks shows in English. A folder groups the catalogues of a large area: `locales/fr/knowledge/ask.json` is the namespace `knowledge/ask`, written `useTranslation('knowledge/ask')` or `'knowledge/ask:path.to.key'`.
- The code: `src/renderer/i18n/` (start-up, language choice, `useLanguage`). The language is chosen in Settings, kept in `localStorage` and applied without a restart; without a choice it follows the system.

## Add a text

1. In a component: `const { t } = useTranslation('settings')`, then `t('about.checking')`. With a count: `t('x.days', { count })` and the keys `days_one` and `days_other`.
2. In a table of data, write the key out with its namespace: `labelKey: 'settings:sections.account.label'`, and call `t(labelKey)` where it is drawn. Never build a key from pieces.
3. Write the English text in `en/<namespace>.json`, then run `npm run i18n:sync` (it gives every other language the English text to translate) and write the translation.
4. Check with `npm run i18n:check`: it lists the keys the code uses and English lacks, the keys nothing uses, and the keys one language has and another does not.

French uses "vous", never "tu". Not translated: `Seshat`, `SeshatOS`, `SeshatCloud`, `MCP`, `OAuth`, `JWT`, `SCIM`, `API`, `CLI`, file names and formats.

## Why prompts are left out

A translated prompt changes what the model does, and the runtime that holds them is shared with another product. So no translation call is allowed in `seshat-runtime`, in `seshat-backend/internal/knowledge/agent/`, in any file whose name contains `prompt`, `systemprompt` or `instructions`, or in `components/chat/richblocks/catalog/` (the blocks the model is told it can draw). The scan tool skips these paths and refuses to run on them, and a test fails if a translation call appears there. A text that a person types or reads but that is also sent to the agent (for instance the message that approves a plan) stays in English.

Not covered yet: native menus, system dialogs, the installer, the e-mails, and the errors of the Go backend (they will carry stable codes).
